# VRoid Studio でキャラを作る

当初計画の Quaternius(CC0のローポリキット)は、モジュラー設計は理想的でしたが画風が素朴で、顔もほぼのっぺらぼうです。「子どもが喜ぶ可愛いキャラ」という一番大事な要件を満たせないと判断し、**VRoid Studio(pixiv製・無料)**に切り替えました。

## なぜ VRoid か

- アニメ調で**最初から可愛い**。日本語UI
- 髪型・目・眉・口・体型・服をGUIで組める。プリセットが豊富
- **お子さんと一緒にキャラを作れる**。「自分が作った子を着せ替える」のは既製アセットより確実に喜ばれる
- VRM は Humanoid ボーンが**規格で決まっている**ので、P0で検証したボーン照合の仕組みがそのまま活きる
- MToon(トゥーンシェーダ)が標準で付いてくる

技術面は検証済みです。`@pixiv/three-vrm@3.5.5` は `three@0.185` と同居でき、読み込み経路は `npm run check:vrm` で 7/7 通っています。

## 手順

### 1. インストール

https://vroid.com/studio から VRoid Studio(Windows / macOS、無料)を入れます。

### 2. キャラを作る

お子さんと一緒にやるのがおすすめです。触るところは多くありません。

- **顔**: プリセットを選んでから、目・眉・口・輪郭を微調整
- **髪型**: プリセットから選ぶ。髪色もここで決める
- **体型**: 身長・頭身。子ども向けなら**頭身を低め(2.5〜4頭身)**にすると可愛くなります
- **衣装**: プリセットのトップス・ボトムス・靴を選ぶ

### 3. 着せ替えのバリエーションを作る

ここが重要です。**同じキャラのまま衣装だけ変えて、複数回書き出します。**

1. キャラが完成したら、その状態で1回書き出す(例: `hime.vrm`)
2. VRoid に戻り、**顔と髪はそのままで衣装だけ変更**して、別名で書き出す(例: `majo.vrm`)
3. これを作りたい衣装の数だけ繰り返す

姫・魔女・騎士など、ファンタジー系で3〜4着あれば最初は十分です。

### 4. 書き出し設定

「撮影・エクスポート」→「エクスポート」→ VRM形式。

- **VRM 1.0 を推奨**(0.x でも読めます。three-vrm が読み込み時に変換します)
- **ポリゴン削減・テクスチャアトラス化を有効に**。子どものタブレットで軽く動くことが最優先です
- テクスチャサイズは 1024px 程度に落とす。2048px は過剰です

### 5. 動作確認

書き出した `.vrm` をこのリポジトリの `assets-raw/` に置いて:

```bash
npm run inspect:vrm assets-raw/hime.vrm
```

中身(humanoidボーン・メッシュ構成・マテリアル・容量)が表示されます。**この出力を私に見せてください。** メッシュがどう分かれているかで、着せ替えの実装方式が決まります。

2体以上あるなら差分も見られます:

```bash
npm run inspect:vrm assets-raw/hime.vrm assets-raw/majo.vrm -- --diff
```

ボーン名が完全一致していれば、メッシュ移植による「髪だけ・服だけ」の差し替えが狙えます。

### 6. アプリで見る

```bash
mkdir -p public/models/vrm && cp assets-raw/hime.vrm public/models/vrm/
npm run build && npm run preview
```

ブラウザで `http://localhost:4173/?vrm=/models/vrm/hime.vrm` を開くと、そのキャラが表示されます。**コードを触らずに確認できます。**

気に入ったら `src/data/catalog.ts` の `VRM_CHARACTERS` に登録すると、起動時から使えます:

```ts
export const VRM_CHARACTERS: VrmCharacterDef[] = [
  { id: 'hime', label: 'おひめさま', file: '/models/vrm/hime.vrm' },
  { id: 'majo', label: 'まじょ', file: '/models/vrm/majo.vrm' },
];
```

## いまの実装状況と、これから決めること

**できていること**: VRM の読み込み、表示、キャラ単位の切り替え、身長に合わせた自動カメラ調整、揺れ物(springBone)の更新、背景切替、しゃしん。

**まだ決めていないこと**: 「髪だけ差し替え」「服だけ差し替え」をどう実装するか。

VRoid の書き出しは、衣装がメッシュとして分かれている場合と、体と一体化している場合があり、設定によって変わります。実物を見ずに実装すると当てずっぽうになるので、`inspect:vrm` の出力を見てから決めます。想定している選択肢は2つです。

| 方式 | 内容 | 向き不向き |
|---|---|---|
| **VRM丸ごと切替** | 衣装ごとに書き出した VRM を切り替える | 確実。ただし組み合わせ(髪Aと服B)ができず、ファイル数ぶん容量が要る |
| **メッシュ移植** | 同じ体から書き出した VRM 間で、髪・衣装のメッシュだけを付け替える | 組み合わせ自由。ボーン名一致と、揺れ物ボーンの移植が要る |

いまは前者で動いています。後者に進めるかは実物次第です。

## 容量について

計画(PLAN §3.3)の「合計10MB以下」は Quaternius のローポリ前提の数字でした。VRM は1体あたり数MB〜十数MBあるので、**この予算は見直しが必要です**。

対策:
- VRoid の書き出し時にポリゴン削減・テクスチャアトラス化・1024px を必ず使う
- それでも大きければ `npm run assets:optimize` で追加圧縮
- PWA のキャッシュ上限は既に 20MB に引き上げ済み(`vite.config.ts`)。体数が増えるならここも上げる

実物のサイズを見てから、同梱する体数と予算を決めましょう。
