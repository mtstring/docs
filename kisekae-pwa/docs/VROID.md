# VRoid Studio でキャラを作る

当初計画の Quaternius(CC0のローポリキット)は、モジュラー設計は理想的でしたが画風が素朴で、顔もほぼのっぺらぼうです。「子どもが喜ぶ可愛いキャラ」という一番大事な要件を満たせないと判断し、**VRoid Studio(pixiv製・無料)**に切り替えました。

技術面は検証済みです。`@pixiv/three-vrm@3.5.5` は `three@0.185` と同居でき、読み込み経路は `npm run check:vrm` で 7/7 通っています。

> **注意**: この開発環境から vroid.com にアクセスできないため、以下のUI名称は確認できていません。バージョンによって表記が違う場合は実際の画面を優先してください。手順の骨格は変わらないはずです。

---

## 全体の流れ

```
VRoid Studio でキャラを作る（30〜60分）
        ↓
衣装を変えて複数回 VRM 書き出し
        ↓
npm run inspect:vrm で中身を確認  ← ここの出力を見て着せ替え方式を決める
        ↓
?vrm=... でアプリに表示して確認
        ↓
catalog.ts に登録
```

---

## 1. インストール

https://vroid.com/studio から無料でダウンロード(Windows / macOS)。iPad版もあります。アカウント登録は書き出すだけなら不要のはずです。

## 2. 新規作成

起動して「新規作成」。ベースとなる素体(女性/男性など)を選びます。**ここは後から体型で調整できる**ので、迷わず進んで構いません。

## 3. 顔をつくる

画面上部のタブで「顔」を選びます。左側に 顔全体 / 目 / 眉 / 鼻 / 口 / 耳 などの項目が並びます。

**やり方のコツ: まずプリセットを選び、それから少しだけいじる。** ゼロからスライダーを触ると沼ります。

子ども向けに可愛くする要点:

| 項目 | 調整 |
|---|---|
| 目 | **大きめに**。顔の中で目が占める割合が大きいほど幼く可愛くなる |
| 目の位置 | やや下げる。顔の中心より下に目があると幼く見える |
| 鼻 | 小さく、控えめに |
| 輪郭 | 丸く。あごを短く |

お子さんに「この目とこの目、どっちがいい?」と選ばせながらやると早いです。

## 4. 髪型をえらぶ

「髪型」タブ → プリセットヘアーから選びます。髪の色もここで変えられます。

自分で髪を描く機能(髪型編集)もありますが、**最初はプリセットで十分**です。凝るのは後でいくらでもできます。

## 5. 体型 — ここが一番効きます

「体型」タブ。**頭身を下げるのが、可愛くするための一番大きなレバーです。**

- 標準は7〜8頭身(リアル寄り)
- **子ども向けなら 3〜4頭身**くらいまで下げる
- 身長も下げる

頭を大きく、体を小さくするだけで、同じ顔でも一気に「子ども向けキャラ」になります。ここは実際にスライダーを動かしてお子さんの反応を見るのが確実です。

## 6. 衣装 — ファンタジー系について正直な話

「衣装」タブ → プリセット衣装から選びます。

**ただし、VRoid標準のプリセット衣装は現代服が中心です**(制服・カジュアルなど)。ご要望の姫・魔女・騎士といったファンタジー系は、標準では揃いません。ここは計画時に見落としていた点です。

現実的な選択肢は2つあります。

### 案A: BOOTH の「VRoid用衣装テクスチャ」を使う(推奨)

https://booth.pm で「VRoid 衣装」「VRoid テクスチャ」で検索すると、ファンタジー系の衣装テクスチャが大量に出てきます。無料〜1,500円程度が中心です。

VRoid の衣装編集で「テクスチャをインポート」すると適用できます。

**この方式は技術的にも都合がいいです。** テクスチャを差し替えるだけなのでメッシュ構成が変わらず、着せ替えが「テクスチャの切り替え」になります。1体のVRMに複数のテクスチャを持たせるだけで済むので、**ファイル容量も劇的に小さくなります**(体ごとに書き出す必要がない)。

### 案B: 標準プリセットで割り切る

現代服のまま、色違いでバリエーションを作る。手間はゼロですが、ファンタジーの要望からは外れます。

まずは案Aを前提に進めるのがよいと思いますが、**最初の1体は標準プリセットのままで構いません**。先にパイプライン全体を通したいので。

## 7. 書き出し(重要)

「撮影・エクスポート」タブ → エクスポート → VRM形式。

### 最初の1体は「削減オプションをすべてオフ」で書き出してください

書き出しダイアログに、メッシュ削減・マテリアル削減(テクスチャアトラス化)・ボーン削減といったオプションがあります。容量は小さくなりますが、**マテリアル削減はメッシュを統合してしまう可能性があり、そうなると「髪だけ差し替え」「服だけ差し替え」ができなくなります。**

なので:

1. **1体目は削減オフで書き出す** → `inspect:vrm` でメッシュ構成を確認する(本来の構造を見るため)
2. その結果を見て、どこまで削減してよいか決める

いきなり削減ありで書き出すと、構造が潰れた状態しか見えず、判断できません。

### その他の設定

- **VRM 1.0 を推奨**(0.x でも読めます。three-vrm が読み込み時に変換します)
- メタ情報(タイトル・作者・利用許諾)の入力を求められます。家庭内利用なので、許諾は一番厳しい設定で構いません

## 8. 中身を確認する

書き出した `.vrm` をこのリポジトリの `assets-raw/` に置いて:

```bash
npm run inspect:vrm assets-raw/mychar.vrm
```

humanoidボーン・メッシュ構成・マテリアル・テクスチャ容量・表情の数が表示されます。**この出力を私に見せてください。** メッシュがどう分かれているかで、着せ替えの実装方式が決まります。

衣装違いを2体以上作ったら、差分も見られます:

```bash
npm run inspect:vrm assets-raw/a.vrm assets-raw/b.vrm -- --diff
```

## 9. アプリで見る

```bash
mkdir -p public/models/vrm && cp assets-raw/mychar.vrm public/models/vrm/
npm run build && npm run preview
```

ブラウザで `http://localhost:4173/?vrm=/models/vrm/mychar.vrm` を開くと表示されます。**コードを触らずに確認できます。**

気に入ったら `src/data/catalog.ts` の `VRM_CHARACTERS` に登録すると、起動時から使えます:

```ts
export const VRM_CHARACTERS: VrmCharacterDef[] = [
  { id: 'hime', label: 'おひめさま', file: '/models/vrm/hime.vrm' },
  { id: 'majo', label: 'まじょ', file: '/models/vrm/majo.vrm' },
];
```

## 着せ替え方式は、実物を見てから決めます

`inspect:vrm` の出力次第で、3つのうちどれを採るかが決まります。

| 方式 | 条件 | 長所 / 短所 |
|---|---|---|
| **テクスチャ差し替え** | BOOTH等の衣装テクスチャを使う場合 | 容量が最小・組み合わせ自由 / 形は変わらない |
| **メッシュ移植** | 衣装が独立メッシュで、ボーン名が一致する場合 | 形も変わる・組み合わせ自由 / 揺れ物ボーンの移植が要る |
| **VRM丸ごと切替** | 上記が使えない場合 | 確実 / 組み合わせ不可・容量が体数ぶん要る |

いまアプリに入っているのは3番目です。1番目が使えるならそれが一番いいので、まずは `inspect:vrm` の結果待ちです。

**推測で実装を進めない方針**にしています。実物を見ずに書くと当てずっぽうになるためです。

## 容量について

計画(PLAN §3.3)の「合計10MB以下」は Quaternius のローポリ前提の数字でした。VRM は1体あたり数MB〜十数MBあるので、**この予算は見直しが必要です**。

- テクスチャ差し替え方式なら、体は1つで済むので予算内に収まる可能性が高い
- 丸ごと切替方式なら、体数ぶん必要。削減オプションと `npm run assets:optimize` で圧縮する
- PWA のキャッシュ上限は既に 20MB に引き上げ済み(`vite.config.ts`)

実物のサイズを見てから決めましょう。

## ライセンス

VRoid Studio で自作したキャラの権利はあなたにあります。家庭内で使うぶんには制約はありません。

BOOTH等で入手した衣装データは、それぞれのライセンスに従ってください。多くは個人利用可・再配布不可です。このアプリは端末内で完結しリポジトリもプライベートなので通常は問題になりませんが、入手したものは `public/CREDITS.md` に出典を残してください。

## 詰まったら

- 顔や体型で迷ったら、プリセットのまま進めて構いません。**まず1体を最後まで書き出すこと**が大事です
- 書き出しでエラーが出る、`inspect:vrm` が読めない、アプリで真っ白になる — そのときはエラーメッセージをそのまま渡してください
